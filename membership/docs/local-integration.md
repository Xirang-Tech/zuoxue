## 如何复测

1. 从统一入口打开任一产品，以 B 组登录。付费墙中原套餐之后展示联合会员板块；账号菜单、侧栏或会员页面提供独立入口。
2. 点击进入会员中心，同一测试账号登录后，来源产品排第一。月卡默认 ¥99；切换年卡 ¥799，两者均明确标注演示价格。
3. 会员中心返回原产品；项目上下文只携带定位 ID。AI PM 支持 `#project/<id>:<workId>`，Workflow 使用 `?projectId=<id>`。
4. 退出并改用 A 组后，产品不显示入口；直接访问中心也不能购买。`variant=B` 等页面参数不能覆盖服务端分组。
5. 需要体验模拟支付、退款和恢复时使用独立 5088 演示。5105 的真实购买始终关闭，没有状态切换器、模拟收款码或付款二维码。
6. 在官网预览点击「会员中心」，确认进入 `5105/account`。用 A 组和 B 组账号核对账号页和套餐展示，再通过「返回佐学官网」返回 5107。「登录佐学账号」仅显示预留提示。

课伴本地没有 AI/转写生产密钥，也没有导入平台运营配置；相关设置接口可能返回 503。本轮入口、登录、付费页和返回可用，不验证转写或模型生成。

## 启动与隔离

要求现有四个源码仓库及其依赖可用、Node 22.14+、Homebrew PostgreSQL 16 和 Redis。`prepare-local-integration.mjs` 从每个仓库 HEAD 导出代码，只叠加审核过的联合会员文件，保留原仓库其他工作区修改。导出清单保存于 `output/local-integration/manifest.json`。不复制 `.env`、真实密钥和业务数据。

首次准备（当前机器已完成）：

```sh
cd /Users/t7/Documents/佐学/membership
npm run local:prepare
npm run local:db
npm run local:start
```

再次启动只执行后两条；准备命令遇到现有源码副本会拒绝覆盖。四款原生登录与计费数据库分别为 `keban_union_local`、`aipm_union_local`、`workflow_union_local`、`pattern_union_local`；中心为 `zuoxue_union_local`。专用 PostgreSQL 仅监听 127.0.0.1:56473，数据位于 `output/local-integration/postgres`，启动器会核对该目录。Redis 仅监听本机，优先使用 56379；若被占用则独立启动在系统分配的空闲端口，实际端口记录在 `output/local-integration/runtime.json`。不会复用或停止占用原端口的服务。服务间随机本地凭证位于忽略提交的 `private-config.json`，权限 600。

产品前端和接口内部端口为 5111–5114、5122–5124，均绑定本机。请使用表格中的 5101–5104 入口代理；这些代理额外拒绝支付、内部权益接口与模型调用。即使访问内部开发端口，也没有配置真实模型和商户密钥。

中心 `DEPLOYMENT_ENV=integration` 强制检查专用本机地址、数据库、独立实验版本与禁用支付；测试账号覆盖不能在 production 启用。实验事件强制标记测试数据，正式 catalog 价格仍为空，演示价格独立读取。

## 停止与恢复

运行联调的终端按 Ctrl+C：仅关闭本启动器创建的产品进程、代理、模拟身份、中心与专用 Redis。原 5088 演示独立运行，不受影响。数据保留，重新 `npm run local:start` 恢复。

需要停止专用数据库时：

```sh
/opt/homebrew/opt/postgresql@16/bin/pg_ctl -D '/Users/t7/Documents/佐学/membership/output/local-integration/postgres' -m fast stop
```

不删除数据、不停止其他 PostgreSQL 实例、不改其他项目配置。源码改动都还在各自工作区，回退时只撤回联合会员相关文件的对应变更，勿对脏工作区执行整体重置。上线前仍需真实 Identity 接入方与跨域会话、AI PRD、成本价格、真实支付退款和全部原生权益的联合验收。
